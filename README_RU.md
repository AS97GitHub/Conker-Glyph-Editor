# Conker Glyph Editor

### Визуальный редактор глифов шрифтов Conker: Live & Reloaded (формат CAFF).

</td>
</tr>
</table>

## Файлы

- `conker_glyph_format.py` — библиотека для чтения и записи формата шрифта и управления хеш-таблицей символов с открытой адресацией (обязательна для работы редактора)
- `conker_glyph_editor.py` — основной графический редактор (tkinter)

Все файлы должны находиться в одной папке.

## Установка (Windows)

### Вариант 1 — Скачать готовый исполняемый файл

Скачайте последнюю версию `.exe` со страницы [Releases](https://github.com/AS97GitHub/Conker-Glyph-Editor/releases).

> Устанавливать `python` и дополнительные зависимости не требуется.

### Вариант 2 — Запуск из исходников

1. Убедитесь, что установлен Python 3.8 или новее (tkinter входит в стандартную поставку Python для Windows, отдельно устанавливать его не нужно).
2. Установите Pillow:

   ```
   pip install Pillow
   ```

## Запуск

> ⚠️ В Windows для запуска скрипта можно использовать `python` или `py` — в зависимости от того, как установлен Python.

> ⚠️ В Linux вместо `python` может потребоваться `python3`.

```bash
python conker_glyph_editor.py
```

Или сразу передайте файлы шрифта и текстуры:

```bash
python conker_glyph_editor.py путь\к\default.bin путь\к\texture.png
```

## Использование

1. **"Open .bin..."** — выберите файл шрифта (например, `default.bin` из `ConkerFont`). **Профиль** (`ConkerFont` / `ConkerFontJapanese` / `FrontendTitle` / `FrontendTitleJapanese`) **определяется автоматически** по байтовой сигнатуре в файле, и выпадающий список обновится соответствующим образом; выбирать профиль вручную нужно только для переопределения автоматического определения.
2. **"Open Texture..."** — выберите извлечённую текстуру для того же шрифта (BMP или PNG, например экспортированную через CrystalTile2, ImageHeat или собственным способом).
3. **Вкладки Glyphs / Charmap:** выбирайте глиф по индексу или ищите назначенные символы на вкладке Charmap. Выбранный глиф подсвечивается на текстуре голубым прямоугольником с угловыми маркерами. Вкладка Charmap также показывает «сырые» пустые слоты фиксированной хеш-таблицы символов.
4. **Визуальное и посимвольное редактирование:**
   - Перетаскивайте угловой маркер, чтобы изменить размер прямоугольника глифа (`x0/y0/x1/y1`).
   - Перетаскивайте центр прямоугольника, чтобы переместить его.
   - Вручную редактируйте метрики на правой панели и нажимайте **"Apply Changes"**:
     - **X Bearing / Y Bearing** — смещение от базовой линии (знаковое, -128..127). Отрицательный X сдвигает глиф влево, положительный — вправо; положительный Y опускает глиф ниже, отрицательный — поднимает выше.
     - **Glyph Width / Glyph Height** — физический размер глифа на экране (растягивает/сжимает глиф по осям X/Y).
     - **Advance Width** — горизонтальный шаг до следующего символа.
5. **Character Management (управление символами):** выберите действие из списка, заполните нужные поля и нажмите **"Apply"**:
   - **add** — привязать к выбранному глифу новый символ или код (один символ или `U+XXXX`) в дополнение к существующим. Дублирующиеся коды отклоняются.
   - **remove** — удалить выбранный в поле **Old Char** символ у выбранного глифа. У глифа остаётся хотя бы один символ; удаление последнего запрещено.
   - **replace** — переназначить символ, выбранный в **Old Char**, на код, введённый в **New Char**.
   - **new_glyph** — добавить новый глиф в конец таблицы глифов как копию выбранного, чтобы его сразу было видно и можно было редактировать. Поле **New Char** необязательно и привязывает символ к новому глифу. Файл увеличивается: все размеры, смещения и контрольная сумма заголовка обновляются автоматически.
   - **delete_glyph** — удалить выбранный глиф: его символы отвязываются, все последующие глифы смещаются на один индекс вниз. Файл уменьшается. Перед удалением запрашивается подтверждение; после сохранения действие необратимо.
6. **Сохранение:**
   - **"Save As..."** — сохранить в новый файл.
   - **"Save (overwrite)"** — перезаписать открытый файл.

Редактор аккуратно изменяет записи глифов и перестраивает фиксированную хеш-таблицу из 2048 слотов, не разрывая цепочки пробирования и не повреждая прочие области файла. При добавлении или удалении глифов контейнер полностью перекладывается (таблица символов, выравнивающий отступ, ресурс текстуры, метаданные, размеры секций), а при сохранении обновляются контрольная сумма заголовка и лимит пробирования таблицы символов — поэтому сохранённый файл всегда принимается игрой.

## Извлечение текстуры через CrystalTile2

Чтобы открыть текстуру шрифта в **CrystalTile2**:

1. Откройте файл шрифта в CrystalTile2.
2. Используйте следующие настройки:

**Default setting**

* **Offset:**

  * `3458` — `ConkerFont`
  * `79F8` — `ConkerFontJapanese`
  * `2EFC` — `FrontendTitle`
  * `407C` — `FrontendTitleJapanese`

**Tile property**

* **Width / Height:**

  * `256×240` — `ConkerFont`
  * `1024×772` — `ConkerFontJapanese`
  * `512×203` — `FrontendTitle`
  * `1024×335` — `FrontendTitleJapanese`

* **Tile form:** `GBA 8bpp`

**Palette**

* **Palette:** `Gray DIVISION`

3. После применения этих настроек экспортируйте текстуру в формате **BMP** или **PNG**.
4. Откройте экспортированную текстуру в **Conker Glyph Editor** через **"Open Texture..."**.

> **Совет:** для редактирования текстуры рекомендуется копировать её напрямую из предпросмотра CrystalTile2 и вставлять в Photoshop. Так сохранится внешний вид текстуры, как она отображается в CrystalTile2.

## Важное примечание

Формула декодирования координат для каждого шрифта:

```
pixel = raw / DIV + OFFSET
DIV   = 16384 / actual_texture_size_in_pixels
```

где 16384 = 2¹⁴ — координаты хранятся в фиксированной 14-битной нормализованной сетке.

Формула координат прямоугольника текстуры (`x0/y0/x1/y1`) получена эмпирически, тогда как параметры отрисовки (**X/Y Bearing**, **Glyph Width/Height** и **Advance Width**) отдельно **подтверждены в игре через XEMU**. При масштабных изменениях проверяйте результат в игре.
