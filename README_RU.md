# Conker Glyph Editor

### Визуальный редактор глифов для шрифтов Conker: Live & Reloaded (формат CAFF).

</td>
</tr>
</table>

## Файлы

- `conker_glyph_format.py` — библиотека для чтения и записи формата шрифта (нужна для работы редактора)
- `conker_glyph_editor.py` — основной графический редактор (tkinter)

Все файлы должны находиться в одной папке.

## Установка (Windows)

### Вариант 1 — Скачать исполняемый файл

Скачайте последнюю версию `.exe` со страницы [Releases](https://github.com/AS97GitHub/Conker-Glyph-Editor/releases).

> Установка `python` и дополнительных зависимостей не требуется.

### Вариант 2 — Запуск из исходного кода

1. Убедитесь, что установлен Python 3.8+ (tkinter входит в стандартный дистрибутив Python для Windows, отдельно ставить не нужно).
2. Установите `Pillow`:
   ```
   pip install Pillow
   ```

## Запуск

> ⚠️ В Windows для запуска можно использовать `python` или `py`, в зависимости от установленной версии Python.

> ⚠️ В Linux вместо `python` может потребоваться использовать `python3`.

```bash
python conker_glyph_editor.py
```

Также программу можно запустить напрямую, указав файлы шрифта и текстуры:

```bash
python conker_glyph_editor.py путь\к\default.bin путь\к\текстуре.png
```

## Использование

1. **"Open .bin..."** — выберите файл шрифта (например `default.bin` из `ConkerFont`). **Профиль** (`ConkerFont` / `ConkerFontJapanese` / `FrontendTitle` / `FrontendTitleJapanese`) определяется **автоматически** по байтовой сигнатуре в файле, и раскрывающийся список обновляется соответствующим образом; выбирать профиль вручную нужно только если вы хотите переопределить определённый автоматически (например, для эксперимента, либо если автоопределение не сработало на нестандартном файле).
2. **"Open Texture..."** — выберите извлечённую текстуру для этого же шрифта (BMP или PNG, например, извлечённую с помощью CrystalTile2, ImageHeat или собственного экспорта).
3. Список глифов слева позволяет выбрать нужный глиф — также в списке показывается символ, на который отображается каждый глиф (см. раздел **"Сопоставление символов"** ниже), если он известен. Выбранный глиф выделяется на текстуре голубым прямоугольником с угловыми маркерами.
4. **Редактирование:**
   - Перетаскивайте угловой маркер, чтобы изменить размер прямоугольника глифа (`x0/y0/x1/y1`).
   - Перетаскивайте центр прямоугольника, чтобы переместить его.
   - Также можно вручную ввести значения в панели справа и нажать **"Apply Changes"**.
   - Помимо прямоугольника, панель также содержит четыре дополнительных поля для каждого глифа, влияние которых на рендеринг подтверждено непосредственно в игре (через XEMU):
     - **X Bearing / Y Bearing** — смещение глифа относительно базовой линии (отрицательное X = влево, положительное X = вправо; положительное Y = ниже, отрицательное Y = выше). Отображается как знаковое значение (-128..127).
     - **Glyph Width / Glyph Height** — физический размер глифа на экране; изменение этих значений растягивает или сжимает глиф по соответствующей оси независимо от размера прямоугольника на текстуре.
     - **Advance Width** — горизонтальный шаг до начальной позиции следующего символа.
5. **Сохранение:**
   - **"Save As..."** — сохранить в новый файл (рекомендуется, чтобы сохранить оригинал).
   - **"Save (overwrite)"** — перезаписать открытый файл (требуется подтверждение).

Редактор изменяет **только байты записи выбранного глифа**: каждая запись занимает слот в 18 байт в таблице глифов, но редактор читает и записывает только первые 16 байт этого слота — именно там расположены все перечисленные выше поля (включая последний байт, во всех наблюдениях равный 0x00). Оставшиеся же 2 байта каждого 18-байтного слота — это **отдельная область, которую редактор вообще никогда не читает и не записывает**. Во всех четырёх тестовых файлах (`ConkerFont`, `ConkerFontJapanese`, `FrontendTitle`, `FrontendTitleJapanese` — суммарно 1879 записей глифов) эти 2 байта равны `FF FF` абсолютно во всех записях без единого исключения. Тем не менее это наблюдение по проверенным тестовым файлам, а не подтверждённый факт о формате — реальное назначение этих байт (если оно вообще есть) неизвестно. Они оставлены нетронутыми, чтобы не повредить что-то ещё не до конца исследованное. Остальная часть файла (текстура, другие глифы, заголовки и т. д.) остаётся полностью неизменной на уровне байтов.

## Сопоставление символов

Редактор автоматически сканирует файл в поисках таблицы сопоставления символов с глифами (без жёстко заданных смещений), поэтому он работает со шрифтами разного размера и структуры, включая CJK-варианты (`ConkerFontJapanese`, `FrontendTitleJapanese`). Именно это заполняет символ, отображаемый рядом с каждым глифом в списке. В графическом интерфейсе это сопоставление доступно только для просмотра; сама библиотека (`conker_glyph_format.py`) дополнительно предоставляет функции `remap_charmap_code()` и `find_codes_in_range()` для программного переназначения того, какой код символа вызывает тот или иной глиф — если это нужно для сценариев на основе скриптов.

## Важное примечание

Формула декодирования координат для каждого шрифта:

```
pixel = raw / DIV + OFFSET
DIV   = 16384 / actual_used_texture_size_in_pixels
```

где 16384 = 2¹⁴ — координаты хранятся в фиксированной 14-битной нормализованной сетке.

Под **"actual used size"** подразумевается реальная ширина/высота содержимого текстуры (например, размер, который выдаёт ImageHeat после обрезки пустых полей: 256×240 для `ConkerFont`, 512×203 для `FrontendTitle`), а не размеры файла текстуры, соответствующие степени двойки.

Эта формула была проверена с помощью **IoU** на реальных текстурах известных шрифтов (среднее перекрытие предсказанных и фактических контуров глифов составляет примерно 0.85–0.87) и использует единую структурно согласованную логику как для X, так и для Y, вместо двух независимо подобранных коэффициентов.

Однако сама формула координат ещё **не была полностью проверена посредством дизассемблирования или отладки кода самой игры** — поэтому теоретически всё ещё возможно **расхождение с тем, как координаты фактически используются игровым движком**, особенно для размеров текстур, которые ещё не были проверены на тестовых образцах. Это уточнение касается именно формулы прямоугольника текстуры (`x0/y0/x1/y1`); остальные редактируемые поля (X/Y Bearing, Glyph Width/Height, Advance Width) отдельно **подтверждены непосредственно в игре через XEMU** — путём изменения одного поля за раз и сравнения скриншотов с неизменённым оригиналом.

Если есть возможность, проверьте внесённые изменения непосредственно в игре (например, используя XEMU). Рекомендуется сначала сделать небольшие изменения и протестировать их, прежде чем использовать редактор для масштабных модификаций.
